Workflow Automation Card

An automation drawn as a flow: what starts it, the yes / no check, the actions on each side, the wait, and what happens last. Turn it on or off, open any step to see its settings, and run a test contact through it step by step.

Example data. Fictional workflow, contacts and numbers, not real client results.

Workflow

Fields

statusAttribute. on or off. The switch updates it. Falls back to JSON enabled.
name · eyebrow · subtitleHeader text.
ref · revisionOptional. Shown in the blueprint title block.
stats{ period, runs, succeeded, avgSeconds, lastRun }. Success rate is worked out from runs.
testContact{ name, note } for the test run bar.
flow[]Steps in order. Each has id, type (trigger, condition, action, wait), title, detail.
flow[].yes · noCondition only. The steps on each branch. Branches join again at the next step.
flow[].test · testDefaultCondition only. Label and starting value of the test switch that picks the branch.
flow[].configSettings shown in the side panel, as { "Label": "Value" }.
flow[].runsContacts that reached the step in the stats period.
flow[].icon · testMsOptional. form, chat, user, mail, list, sms, clock, phone, task, bell; fixed test-run time in ms.

Usage

<workflow-automation status="on">
  <script type="application/json">
    {
      "name": "New lead follow-up",
      "flow": [
        { "id": "t", "type": "trigger", "title": "Form submitted" },
        { "id": "c", "type": "condition", "title": "Has tag: VIP?",
          "test": "Has VIP tag",
          "yes": [{ "id": "a", "type": "action", "title": "Notify team chat" }],
          "no":  [{ "id": "b", "type": "action", "title": "Send welcome email" }] },
        { "id": "w", "type": "wait", "title": "Wait 1 day" }
      ]
    }
  </script>
</workflow-automation>

// or from data, and drive the test run:
el.data = { name, flow: [...] };
el.run();  el.pause();  el.stop();

The test run follows the branch picked by each test switch and logs every step with its time. It fires workflowrun when a run starts, pauses, resumes, stops or completes. The switch fires workflowtoggle, and opening a step fires nodeselect.
